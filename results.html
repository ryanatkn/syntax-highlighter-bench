syntax-highlighter-bench results

Timed on laptop1 (AMD Ryzen 5 PRO 7530U with Radeon Graphics, Node v24.14.1) on 2026-10-11 at commit bd12c165af. The machine's noise floor is 2.3% for one cell and 0.3% for a geometric mean: a smaller difference is not a result. The method says how each number is measured and what it leaves out.

The machine and the run

laptop1: AMD Ryzen 5 PRO 7530U with Radeon Graphics, 12 threads, performance governor, amd-pstate-epp driver, energy preference performance, boost on, 14.4 GB, kernel 6.12.90+deb13.1-amd64. Corpus e649d70d43. The anchor, a fixed workload read before and after measuring, drifted 2.2%: stable. Two processes measuring the same library on the same cell in this run were 4.0% apart at the 95th percentile and 0.9% at the median, against 4.1% at the 95th percentile in the calibration.

Each row is one thing measured, with a column for each library. Beside a number is its ratio to the best in the row, or to a reference library you choose: 1.00× is the baseline and 2.00× is twice as slow or twice as large. In the tables whose ratios aren't colored, where a smaller number isn't a better one, the baseline is the smallest. A library with no number in a row says why: unsupported when its adapter doesn't claim the language, and excluded when it claims it and its output failed the check that runs before measuring. Neither is a zero, and neither enters a mean.

Cold start

Loaded as

What each library adds to a fresh Node process: the scenario's median time less bare Node's. A row's details give the whole time and the process's peak memory.

How to read this table

Bundled is the one chunk whose size is reported below, and unbundled imports the same entry with its imports resolved from node_modules. A ratio between small additions is large even when the processes take nearly the same time.

An addition smaller than bare Node's own band, from its 10th to its 90th percentile, is marked in the noise: it can't be told from adding nothing, and has no ratio. In a row with such an addition the others are compared with that band instead of with the best, and marked ≥: at least so many times the band, and so at least so many times the best, which is inside it. Such a row is left out of the mean. A reference library is used only in the rows where its own addition is outside the noise.

Bundle size

What each language costs in a library's minified JS: the floor with no language, the first language, and one more beside the others.

How to read this table

The first language is the bundle with that language alone, less the bundle with none. One more language is what it adds to a bundle of every other timed language, always in minified bytes, whatever the Bytes selector says: compressing a whole bundle doesn't separate one part of it. The floor plus each language alone is not a bundle, so it has no ratio: it exceeds the set's measured size when a library shares code between languages, or when one language brings another with it, as HTML brings the script and style languages. The wasm binary and the theme stylesheet are loaded beside the JS, and each has a row of its own.

Retained heap

Parts

What a process holds once a library has loaded one language and highlighted a small snippet once, over a bare process: a smaller figure is less memory for the same highlight.

How to read this table

A Node process imports the library's bundle of that language alone, the one whose size is reported above, highlights the language's snippet, lets go of the HTML, and collects garbage until the heap settles. Larger inputs leave more, most of all for regexp and wasm engines.

Machine code holds the regular expressions the engine compiled as well as optimized functions, and is the processor's: these figures are x64's. External memory is where a WebAssembly engine keeps its linear memory, counted at the size it has grown to, which it never gives back; the OS backs only the pages it has touched, so resident memory can be lower. The sum of the three is shown first and ranked, so neither a regexp engine nor a wasm engine is compared without what it holds; the Parts filter shows each on its own. A ratio within the heap check's tolerance is marked ≈.

A theme in a stylesheet is held by the page, not the library, so a library that writes its styles inline holds its theme here and one with classes doesn't. The figures are for one Node version; the deterministic metrics docs say which, and what moves them.

How to read this table

The ratios are to the smallest in each row and are not colored, because smaller is not better here: libraries split the same source differently and wrap their HTML differently, so fewer tokens is a coarser split, not a better one, and HTML with inline styles carries its theme where HTML with classes leaves it to a stylesheet. The deterministic metrics docs say what each counts.
